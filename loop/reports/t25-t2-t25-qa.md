## 3. LT10 源码、Avian 依据与测试

### 捕获边界

`src/pie.rs` 的 Path B 从 `register_entity_in_ast` 转至 `register_promoted_entity_in_ast`。专用函数复刻共享注册的 dead entity、缺 AST、已有 node、稳定 ID、parent linking 与每组件 upsert；额外过滤只作用在 promote 捕获面，Path A 仍使用原 `preview_entity_components_as_bsn`。来源 `src/scene_io/registration.rs` 的共享 guard/遍历未变。

关系过滤使用两个**确切 type path + Entity 反射验证**，不以 Avian 模块前缀过滤：

- `avian3d::collision::collider::collider_hierarchy::ColliderOf`：Avian 源码是 `Relationship`，字段 `body: Entity`。
- `avian3d::collision::collider::collider_hierarchy::RigidBodyColliders`：Avian 源码为 relationship target，内容 `Vec<Entity>`，由 `ColliderOf` 自动维护。

在本机锁定的 avian3d 0.8.0 源码中，`ColliderOf::on_insert` 读取 body bits 并维护目标列表，`RigidBodyColliders` 文档明确不应手工修改。单测实际创建 `RigidBody` body + `ColliderOf { body }` collider，flush hook 后确认 body 上真实出现 `RigidBodyColliders`，再分别 promote 验证两个关系不写节点。不是只构造一个含名字的空 mock。
